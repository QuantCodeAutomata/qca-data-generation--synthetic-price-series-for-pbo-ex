# AGENTS.md — Repository Knowledge Base

## Project Overview
CSCV / PBO research repository implementing the Combinatorially Symmetric
Cross-Validation algorithm from Bailey et al. (2014) on two synthetic daily
return series to validate backtest overfitting detection.

## Architecture

### Source modules (src/)
| Module | Purpose |
|--------|---------|
| `data_generation.py` | Generate returns_ex1/ex2, business-day calendar, price series |
| `strategy_simulation.py` | Simulate 8,800 monthly seasonal strategies → T×N P&L matrices |
| `cscv.py` | Full CSCV: partition, aggregate stats, SR, logit λ, PBO, regression |
| `analysis.py` | Empirical CDF, stochastic dominance (FO/SO), PSR (Bailey 2014) |
| `visualization.py` | All matplotlib/seaborn plots → results/ dir |

### Experiment scripts (exp/)
Run in order: exp1 → exp2 → exp3 → exp4 → exp5 → exp6.
exp5 must run before exp6 (exp6 loads PSR scalars saved by exp5).

## Key Parameters
- T = 1000 daily observations; T_adj = 992 (divisible by S=16)
- sigma = 0.01 (daily vol); seasonal shift = 0.25 * sigma_full_ex1
- Seasonal days: first 5 business days of each calendar month
- Strategy grid: 20 × 20 × 11 × 2 = 8,800 combinations
- CSCV: S=16 partitions, C(16,8)=12,870 combinations

## Key Implementation Notes

### CSCV Performance
- Pre-compute `sum_s` and `sumsq_s` (16×8800) before the 12,870-combination loop
- Use full numpy vectorisation: SR is computed for all 8800 strategies at once per combination
- Expected runtime: ~10-15 seconds for the CSCV loop on modern CPU

### PSR Formula
Uses excess kurtosis convention (scipy.stats.kurtosis, fisher=True):
```python
PSR_stat = SR_hat_daily * sqrt(T-1) / sqrt(1 - γ3*SR + (γ4_excess+2)/4 * SR^2)
```

### Stochastic Dominance (Example 2 note)
Distribution A (IS-optimal OOS SR) has higher mean than B (mean OOS SR), but
does NOT achieve strict first-order dominance because A has a fat left tail
(range: -2.4 to +2.0) while B is narrow (range: -0.07 to +0.09).
The PBO contrast (0.79 vs 0.17) is the primary discriminating metric.

### Strategy Simulation
- `simulate_strategies` groups strategies by (e,h,s) to vectorise long/short pair
- Stop-loss: cumulative P&L < -s * sigma_daily triggers early exit
- Entry map pre-computed once per month per entry_day for O(1) lookup
